## 二、CLI 契约（首期三条命令闭环 + 辅助命令）

### 2.1 命令总表

| 命令 | 用途 | 题目文档对应 | 首期 |
|---|---|---|---|
| `picrecall index <folder> [--db PATH] [--json]` | 建/更新索引（扫描 + 变更检测） | 提交材料①"建索引" | ✅ |
| `picrecall ocr [--db PATH] [--retry-failed] [--limit N] [--json]` | 对新增/变更图跑 OCR | 模块 2 | ✅ |
| `picrecall search <query> [--db PATH] [--limit N] [--json]` | 按文字检索 | 提交材料①"检索" | ✅ |
| `picrecall dedupe [--db PATH] [--out FILE] [--json]` | pHash 分组 + 保留建议清单 | 提交材料①"重复合并建议" | ✅ |
| `picrecall bench gen [--out DIR]` | 生成合成截图集 + manifest | 模块 5 | ✅ |
| `picrecall bench run [--data DIR] [--json]` | 真值对账（识别率 + 命中率） | 模块 5 | ✅ |
| `picrecall selftest` | 冻结态自检（依赖/数据/口径探活） | 交付 | ✅ |
| `picrecall stats [--db PATH]` | 索引库状态速览 | 辅助 | ✅ |

**三条命令闭环（README 快速开始逐字给出）**：
```
picrecall index <截图文件夹>      # 1. 建索引
picrecall ocr                     # 2. 识别（首建索引后必跑，否则检索无内容）
picrecall search "<查询词>"        # 3. 检索
picrecall dedupe                  # 4. 重复合并建议（只读）
```

> 注：题目文档"三条命令"指 建索引 → 检索 → 重复合并建议；OCR 作为建索引后的必要步骤在 README 中并列给出（4 条），**不改变"闭环"性质**。此偏差在 plan/06 对照表与 HANDOFF-M1 如实记录。

## 三、模块 1：索引（FR-1..FR-4）

```
scan_folder(folder, exts) -> list[FileEntry]
    # 递归 rglob；exts 白名单（一处定义于 config.SUPPORTED_EXTS）
    # 路径 os.path.abspath + normcase 归一；结果 sorted(path) 确定性
apply_scan(conn, entries, profile) -> ScanResult(added, changed, unchanged, missing)
    # 对每文件：读 size/mtime_ns；与库中记录比对
    #   新 path              -> status=pending（待 OCR）
    #   同 path 且 size+mtime_ns 同 -> 跳过（快速路径，不重算 hash）
    #   size/mtime 变        -> 重算 sha256；hash 同则 unchanged（只更新 mtime_ns）
    #                           hash 异 -> status=pending（变更，需重识别）
    # 库中有、本次扫描未见      -> status=missing（只标记，不删行、不动文件）
```

纪律落点：
- **不动用户文件**：全模块只有 `SELECT/INSERT/UPDATE`（在索引库上），无任何 `os.remove/os.rename/os.replace` 作用于用户文件夹。测试含"跑完后用户文件 mtime/size/存在性不变"断言。
- **重跑一致**：同一文件夹连跑两次 → `added=0, changed=0`；`unchanged` 计数一致。
- **hash 与内容绑定**：`file_hash` 变化即触发重识别，`run_sig` 随之变化。

## 四、模块 2：OCR 管线（FR-5..FR-7）

```
ocr_pending(conn, limit=None, retry_failed=False) -> OcrReport(ok, failed, skipped)
ocr_one(engine, path) -> OcrResult(text, lines[], mean_conf)
```

纪律落点：
- **批量 + 失败隔离**：单张抛异常 → 该文件 `status=ocr_failed`、`ocr_tries+=1`、`ocr_error` 记原因，**不中断整批**。
- **可续跑**：`--retry-failed` 把 `ocr_failed` 重新纳入待办；`ocr_tries` 递增可观测（续跑不重复计已成功项）。
- **阈值一处定义**：`config.OCR_CONF_MIN`；低于阈值的行**仍入库**（保留原文）但计入 `low_conf_lines`，用于口径核验；是否算"检出"由基准口径决定（plan/05 §四）。
- **重跑一致方可覆盖**：`run_sig = sha256(file_hash | engine_version | OCR_CONF_MIN | profile)`；写入前比对，签名不同 → **不覆盖**，报告"输入已变，需重建"（防陈旧结果覆盖新内容）。
- **引擎缺席走 exit 3**：`import rapidocr_onnxruntime` 失败 → 显式契约错误，不抛裸异常（惰性导入纪律：`try` 包住**从 import 到调用完成**整条路径）。

## 五、模块 3：FTS5 检索（FR-8..FR-10）

```
segment(text, profile) -> str        # 纯函数，索引期与查询期共用
search(conn, query, limit) -> list[Hit(file_id, path, snippet, line_no, score)]
```

- 分词双路径见 plan/03 §三；`meta.tokenizer_profile` 不匹配 → exit 2（提示重建）。
- **排序稳定**：`ORDER BY rank, files.path, chunk.line_no`；rank 为 FTS5 内建 bm25，路径与行号为决定性 tie-breaker。
- **同查询重复执行结果一致**：测试双跑 `search()` 断言序列逐项相等（含顺序）。
- **snippet**：用 FTS5 `snippet()` 高亮，CLI 输出 `路径:行号: 高亮片段`；缩略图路径按题目文档要求输出（`--thumbs DIR` 可选生成，扩展面留 HTML）。
- **零命中 = exit 0**（合法空结果），不是错误。

## 六、模块 4：重复截图合并（FR-11）

```
phash_groups(conn, threshold) -> list[Group(members[], representative, max_distance)]
write_keep_suggestions(groups, out_path) -> Path
```

纪律落点：
- **默认只读，绝不自动删除**：本模块**无任何删除代码路径**；`write_keep_suggestions` 只写 CSV。测试断言"调用前后用户文件夹文件集合不变"（变异验证：注入一个删除调用 → 测试必须红）。
- **阈值一处定义**：`config.PHASH_MAX_DISTANCE`（汉明距离），CLI 可 `--threshold` 覆盖但**默认值来自 config**。
- **保留建议规则**（写进 CSV 与 README，可解释）：组内**优先保留**（1）分辨率更高者 →（2）文件更大者 →（3）mtime 更新者 →（4）路径字典序小者（决定性 tie-breaker）。建议列 = `keep|redundant`，**不执行**。
- **分组确定性**：pHash 计算确定性；分组用并查集/单链聚类，成员与组顺序按 `path` 排序 → 可复跑。

## 七、模块 5：真值基准（FR-12..FR-13）

详见 [plan/05-数据计划.md](05-数据计划.md) §三/§四。要点：
- `gen_synthetic(out_dir, seed)`：确定性 RNG（自研 splitmix64）+ PIL 渲染白名单文本 + 写 `manifest.json`（图片→渲染文本→应命中查询词→版式参数）。
- `run_bench(data_dir)`：**不重算真值**，只从 manifest 读期望，运行时实算观测（识别率/命中率），双向对账。
- 口径一处定义（`bench.py` 顶部常量 + docstring 锚定），文档只引用。

## 八、辅助模块

- `config.py`：**全部数值口径唯一来源**（扩展名白名单、OCR 阈值、pHash 阈值、排序权重、退出码常量、schema 版本）。文档只引用不复述（skill"数值口径只有一处"）。
- `serialize.py`：确定性写盘单点（`write_json_atomic` / `write_csv_atomic` / `write_text_atomic`），参数冻结：`sort_keys=True, ensure_ascii=False, indent=2` + LF + 结尾换行 + 原子 rename。
- `selftest.py`：冻结态自检——① 数据目录可解析；② 关键依赖探活（OCR/imagehash/PIL，缺席走 exit 3 契约）；③ 口径常量自检（阈值在合法区间、退出码常量齐备）；④ schema 版本与代码常量一致。
- `cli.py`：`_ensure_utf8_stdio()` 按 `stream.encoding` 探针决定是否 reconfigure；**所有子命令入口先调用它**（编码守卫覆盖全部会打印的入口）。
