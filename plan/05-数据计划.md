## 二、白名单文本集纪律（`data/whitelist_texts.txt`）

- 覆盖场景形态：聊天短句 / 报错信息 / 菜单项 / 金额文本 / 配置项 / 日期编号。
- **禁止真实个人信息**：号码用假号段（`19900000000` 类）、单号用假值、姓名用通用词（"张三"类占位可，真实姓名不可）。
- **假值也登记**：白名单文件即登记处（data/README §三要求"登记于白名单文件"）。
- **与 manifest 的关系**：白名单是**渲染素材源**；manifest 是**每张图用了哪些行 + 应命中哪些查询词**。两者分开，白名单增删不影响既有 manifest（manifest 记录实际使用行）。

## 三、合成截图集与真值植入（模块 5）

### 3.1 生成器（`bench.gen_synthetic`）

```
gen_synthetic(out_dir, seed=20261016, count=N) -> manifest_path
```

| 维度 | 设计 | 目的 |
|---|---|---|
| 底图 | 纯色/浅噪（确定性噪声，自研 RNG） | 模拟截图底 |
| 版式 | 多形态：纯文本块 / 模拟窗口标题栏 / 模拟对话气泡左右对齐 / 列表项 | 覆盖真实截图形态 |
| 字号 | 多档（小/中/大），字体优先 msyh/arial，缺失回落默认字体 | 覆盖 OCR 尺度敏感性 |
| 文本行数 | 1–5 行/图 | 覆盖稀疏与密集 |
| 文本来源 | `data/whitelist_texts.txt` 按 seed 抽样 | 可控、可复现 |
| 命名 | `img_0001.png` … 序号固定，**不含时间戳** | 位级可复现 |
| 落盘 | PNG（Pillow 默认压缩参数固定）+ LF 无关（二进制）；manifest 用 `serialize.py` | 双跑一致 |

### 3.2 manifest 结构（真值唯一口径）

```json
{
  "schema": "picrecall-bench/1",
  "seed": 20261016,
  "generator": "picrecall.bench",
  "generator_version": "0.1.0",
  "images": [
    {
      "file": "img_0001.png",
      "lines": ["本月账单已生成", "config error: timeout 3000"],
      "queries": ["账单", "config", "timeout"],
      "layout": {"kind": "plain", "font_size": 28, "line_count": 2},
      "sha256": "<图片内容 sha256>"
    }
  ]
}
```

**纪律（K14）**：manifest **只存输入与期望**——`lines`（渲染了什么）、`queries`（应命中什么）、`layout`（怎么渲染的）、`sha256`（产物指纹）。**绝不存 `observed`/`recognized`/`hit_rate` 一类观测字段**——观测由 `run_bench` 运行时实算，否则基准退化成"比对两份预先算好的答案"。

## 四、基准口径声明（识别率 + 命中率，一处定义）

### 4.1 OCR 识别率口径

- **单位**：文本行（line），不是字符、不是整图。
- **"应识别出的文本行"** = manifest 中该图的 `lines` 条目。
- **"被检出"判据**：该行文本经归一化（去空白差异：全角/半角空格、首尾空白）后，**其字符序列包含于** OCR 输出行之一（归一化后），且该输出行置信度 `≥ config.OCR_CONF_MIN`。
- **识别率** = `Σ 检出应识别行数 / Σ 应识别行数`。
- **口径实现位置**：`bench.py` 顶部常量 + docstring 锚定；**不另写第二份**（文档只引用）。
- **已知取舍（如实声明）**：以"包含"而非"逐字相等"判据，是因为 OCR 对中文标点/空格常有不稳定差异（实测 smoke：`error:timeout3000` 空格丢失）；该取舍使识别率口径**偏宽松**，README 与基准报告均显式声明。

### 4.2 检索命中率口径

- **单位**：查询词（query），以 manifest 的 `queries` 为真值。
- **命中判据**：`search(query)` 返回的图片集合**包含** manifest 中声明该 query 的图片文件集合（召回优先）。
- **命中率** = `Σ 完全召回 query 数 / Σ query 数`。
- **精确率另记**：同时记录"返回集中不属于该 query 真值集的图片数"，**如实报告**（不因偏宽松而掩盖误召回）。

### 4.3 双向对账与分层（skill 阶段 5 纪律）

| 层 | 内容 | 是否读 manifest |
|---|---|---|
| 样本驱动层 | 逐图/逐 query 对账，输出明细表 | ✅ 读期望 |
| 规则驱动层 | 机制推导边界：全空白图应 0 行检出、单字符图应命中其字符、超长文本图不应崩溃 | ❌ **不读 manifest**（专治样本没覆盖的端点） |

**达标门槛随 manifest 下发**（数据非代码）：`manifest.thresholds = {"ocr_line_recall": 0.90, "query_recall": 0.90}`；`run_bench` 从 manifest 读门槛，**不硬编码在代码里**。未达标 → exit 1（检出问题语义）。

### 4.4 可证伪探活（防"基准空转"）

基准必须能被**注入缺陷后打红**：
- `run_bench --inject-defect ocr_drop` → 人为丢弃一半识别行 → 识别率必跌破门槛 → exit 1；
- `run_bench --inject-defect search_drop` → 检索返回集裁剪 → 命中率必跌破门槛 → exit 1；
- 这两个开关的存在使"基准绿"成为**可证伪**结论，而非空转（skill"探活打在消费处"）。

## 五、确定性生成纪律（K13）

| 面 | 落法 |
|---|---|
| RNG | 自研 splitmix64（禁 stdlib `random`——不承诺跨版本序列一致）；seed 固定 |
| 迭代序 | 禁 `set` 迭代序；一切列表显式 `sorted()` |
| 时钟 | 禁 `time.time()` / `datetime.now()` 进入产物；无时间戳 |
| 落盘 | `serialize.py` 单点；manifest 双跑逐字节一致，配 `gen --check` 守门测试 |
| 图像 | PNG 无时间戳元数据（Pillow 默认不写 `tIME` chunk，M1 实测确认）；`sha256` 记入 manifest 供指纹核验 |

**`gen --check` 守门**：重新生成到临时目录 → 与既有 manifest 逐字节比对 → 差异即红。**图片本体**按 `sha256` 比对（manifest 内已登记）——**不把图片本身入 git**，故"位级一致"以 manifest 的 sha256 为锚，可核验且不污染仓库体积。

## 七、隐私与合规

- 合成数据用假值，**不含任何真实个人信息**（data/README §三）。
- 真实用户截图**永不入库**（索引库 `*.db` 不入 git；合成图不入 git）。
- 运行期零出网（模型随 wheel 自带，无下载行为；见 plan/03 §四实测勘误）——"零上传"因此成为**可扫产物断言**的性质，而不仅是声明。
