## 二、白名单文本集纪律（`data/whitelist_texts.txt`）

- 覆盖场景形态：聊天短句 / 报错信息 / 菜单项 / 金额文本 / 配置项 / 日期编号。
- **禁止真实个人信息**：号码用假号段（`19900000000` 类）、单号用假值、姓名用通用词（"张三"类占位可，真实姓名不可）。
- **假值也登记**：白名单文件即登记处（data/README §三要求"登记于白名单文件"）。
- **与 manifest 的关系**：白名单是**渲染素材源**；manifest 是**每张图用了哪些行 + 应命中哪些查询词**。两者分开，白名单增删不影响既有 manifest（manifest 记录实际使用行）。

## 三、合成截图集与真值植入（模块 5）

### 3.1 生成器（`bench.gen_synthetic`）

```
gen_synthetic(out_dir, seed=20261016, count=N) -> manifest_path
```

| 维度 | 设计 | 目的 |
|---|---|---|
| 底图 | 纯色/浅噪（确定性噪声，自研 RNG） | 模拟截图底 |
| 版式 | 多形态：纯文本块 / 模拟窗口标题栏 / 模拟对话气泡左右对齐 / 列表项 | 覆盖真实截图形态 |
| 字号 | 多档（小/中/大），字体优先 msyh/arial，缺失回落默认字体 | 覆盖 OCR 尺度敏感性 |
| 文本行数 | 1–5 行/图 | 覆盖稀疏与密集 |
| 文本来源 | `data/whitelist_texts.txt` 按 seed 抽样 | 可控、可复现 |
| 命名 | `img_0001.png` … 序号固定，**不含时间戳** | 位级可复现 |
| 落盘 | PNG（Pillow 默认压缩参数固定）+ LF 无关（二进制）；manifest 用 `serialize.py` | 双跑一致 |

### 3.2 manifest 结构（真值唯一口径）

```json
{
  "schema": "picrecall-bench/1",
  "seed": 20261016,
  "generator": "picrecall.bench",
  "generator_version": "0.1.0",
  "image_count": 60,
  "thresholds": {"ocr_line_recall": 0.90, "query_recall": 0.90},
  "images": [
    {
      "file": "img_0001.png",
      "lines": ["本月账单已生成", "显示行号"],
      "queries": ["本月账单", "显示行号"],
      "layout": {"kind": "bubble_right", "font_size": 24, "line_count": 2, "width": 520, "height": 136},
      "sha256": "<图片文件字节 sha256>",
      "pixel_sha256": "<解码像素 sha256，跨 Pillow 版本稳定>"
    }
  ]
}
```

**纪律（K14）**：manifest **只存输入与期望**——`lines`（渲染了什么）、`queries`（应命中什么）、`layout`（怎么渲染的）、`sha256`（产物指纹）。**绝不存 `observed`/`recognized`/`hit_rate` 一类观测字段**——观测由 `run_bench` 运行时实算，否则基准退化成"比对两份预先算好的答案"。

**双指纹口径（M1 新增，D-16）**：
- `sha256`：**文件字节**指纹，用于"磁盘文件 vs 登记值"的**严格完整性**判定（篡改必红）；
- `pixel_sha256`：**解码像素**指纹，跨 Pillow 版本稳定（实测 10.4.0 vs 12.3.0 像素 0 差异而字节不同），
  用于区分"编码器差异（内容一致，非漂移）"与"内容真的漂移"。
- ⚠️ **不得用像素一致放行字节不一致**：尾部追加字节不改像素，若以像素放行，篡改会被误判成编码器差异，守门即失效。

### 3.3 近似重复族子集（`bench.gen_dupes`，M2）

**为何另建**：M1 已入仓的 `data/synthetic/manifest.json` 登记了每图 `sha256`/`pixel_sha256`，
任何改动都会让 M1 留档的基准数字失效。故近似重复族**另起独立子集**（独立 seed），主集分毫不动。

**要解决的问题**：M0/M1 的 `dedupe` 在主集上实测 **0 组**（版式各异，合法空结果，K8）。
0 组的绿只证明"没崩"，**不证明分组逻辑正确**——缺"能真出组"的端到端样例。

```
gen_dupes(out_dir, seed=20261017, count=6) -> manifest_path
```

| 维度 | 设计 | 实测依据（M2，60 族逐一标定） |
|---|---|---|
| 每族成员 | 3 张：同一底图派生，仅缩放/编码不同 | 族内最大 pairwise 距离 **6**（阈值 8） |
| 成员规格 | PNG 1.00 / PNG 1.15 / **BMP 0.95** | 族间最小距离 **56**（不误并） |
| 低分辨率成员用 BMP | 使 K11 第①级(分辨率)与第②级(大小)判决**相反** | 60/60 族解耦 → 代表选择有区分度 |
| 为何不用位移 | pHash **不抗平移**：平移 2px 距离即 **26**、12px 达 120 | 位移不可用作近似重复的构造手段（D-19） |
| 为何不用亮度 | 亮度可落阈值内（2–4），但正/反向极端亮度两成员间擦边 8–10 | 无余量，故弃用 |

**纪律**：族 manifest 与主集同口径（K14）——只存 `family_id`/`role`/`scale`/`format`/`lines`/`queries`/`layout`/双指纹，
**观测**（实际分了几组、谁是代表）一律不入 manifest，由测试运行时实算。

**已知缺口（如实登记）**：只覆盖"缩放 + 编码"两种形态；**未覆盖**旋转、水印、裁切等真实重复形态，
它们是否仍落阈值内**本轮未实测**（plan/06 风险表已登记）。

## 四、基准口径声明（识别率 + 命中率，一处定义）

### 4.1 OCR 识别率口径

- **单位**：文本行（line），不是字符、不是整图。
- **"应识别出的文本行"** = manifest 中该图的 `lines` 条目。
- **"被检出"判据（M1 校准，D-15）**：该行文本经归一化（去空白差异：全角/半角空格、首尾空白）后，
  **其字符序列包含于** OCR 输出行的**连续若干条拼接串**（归一化后），且参与拼接的输出行置信度
  **均** `≥ config.OCR_CONF_MIN`。
- **为何是"连续若干条"而非"单条"**：实测 OCR 会把**同一条渲染行**切成多个相邻检测框
  （`config error: timeout 3000` → `config` + `error:timeout3000`），只认单条会**系统性低估**
  正确识别（60 图集实测 0.8909 → 0.9545，跨门槛）。
- **识别率** = `Σ 检出应识别行数 / Σ 应识别行数`。
- **宽松度可见**：报告**同时**给出严格单条口径（`recall_strict_single_line` + `strict_line_hits`），
  README 与留档按"两个口径都报"判读，不藏宽松的那个。
- **口径实现位置**：`bench.py` 顶部常量 + docstring 锚定；**不另写第二份**（文档只引用）。
- **已知取舍（如实声明）**：以"包含"而非"逐字相等"判据，是因为 OCR 对中文标点/空格常有不稳定差异
  （实测 smoke：`error:timeout3000` 空格丢失）；该取舍使识别率口径**偏宽松**。


### 4.2 检索命中率口径

- **单位**：查询词（query），以 manifest 的 `queries` 为真值。
- **命中判据**：`search(query)` 返回的图片集合**包含** manifest 中声明该 query 的图片文件集合（召回优先）。
- **命中率** = `Σ 完全召回 query 数 / Σ query 数`。
- **精确率另记**：同时记录"返回集中不属于该 query 真值集的图片数"，**如实报告**（不因偏宽松而掩盖误召回）。

### 4.3 双向对账与分层（skill 阶段 5 纪律）

| 层 | 内容 | 是否读 manifest |
|---|---|---|
| 样本驱动层 | 逐图/逐 query 对账，输出明细表 | ✅ 读期望 |
| 规则驱动层 | 机制推导边界：全空白图应 0 行检出、单字符图应命中其字符、超长文本图不应崩溃、坏图/空文件夹不崩、无命中查询返回空 | ❌ **不读 manifest**（专治样本没覆盖的端点） |

**M4 落地（D-22）**：规则层实现于 `bench.run_rule_probes(conn, inject_defect=None)`，
**签名与函数体均不得出现 manifest**——输入（探针图）由本层当场渲染/写盘，"输入是什么"由构造给定，
故"期望是什么"可由机制直接推出，**没有任何理由**去读真值文件；读了就退化成"第二个样本层"。
该纪律由 `tests/test_bench_rules.py` **三重证伪**：① AST 扫描（规则层源码不得出现 `manifest` 标识符）；
② 把 `_resolve_manifest` 打成抛异常 → 结论逐项不变；③ 删掉 manifest 文件 → 结论逐项不变
（实测：删 manifest 后样本层因找不到真值而报错，规则层结论**逐项相同**）。
规则层在本层自建的**独立临时索引库**上跑，不污染调用方库；报告单列 `report["rules"]`，
细节一律用**相对文件名/固定标签**（不含绝对路径或时钟）。

**达标门槛随 manifest 下发**（数据非代码）：`manifest.thresholds = {"ocr_line_recall": 0.90, "query_recall": 0.90}`；`run_bench` 从 manifest 读门槛，**不硬编码在代码里**。未达标 → exit 1（检出问题语义）。

**M4 定案（D-22）：门槛按 profile 分设**（`manifest.thresholds_by_profile`）。
定标依据（M4 实测，同一 60 图集）：两 profile 的 OCR 行识别率**完全相同**（0.9545），
差异**只在**检索侧；`simple` 的 5 处漏召回中 3 处根因是真值查询"取最长 CJK 片段前 4 字"
截断在词中间（词级语义下跨词边界的子串不可命中），另 2 处（`failed`/`invalid`）是 OCR 切框、
**两 profile 同源同受影响**。故 `simple` 的检索门槛按词级语义另定（0.80），**不是把统一门槛
下调凑数**，也**未改任何已入仓真值**（D-18 红线）。**口径唯一**：manifest 声明
`thresholds_by_profile` 即按 profile 取生效门槛，未声明则退回统一门槛，**不并存两套默认**。

### 4.4 可证伪探活（防"基准空转"）

基准必须能被**注入缺陷后打红**：
- `run_bench --inject-defect ocr_drop` → 人为丢弃一半识别行 → 识别率必跌破门槛 → exit 1；
- `run_bench --inject-defect search_drop` → 检索返回集裁剪 → 命中率必跌破门槛 → exit 1；
- **M4 扩面**：规则层同样可证伪——`--inject-defect rule_blank_always_true`（空白判定恒真）
  使**单字符探针**失守；`--inject-defect rule_bound_ignored`（行数上界判定恒真）使**上界自检**失守。
  两者均实测 exit 1（见 `plan/verify` §M4 四）。
- 这些开关的存在使"基准绿"成为**可证伪**结论，而非空转（skill"探活打在消费处"）。

## 五、确定性生成纪律（K13）

| 面 | 落法 |
|---|---|
| RNG | 自研 splitmix64（禁 stdlib `random`——不承诺跨版本序列一致）；seed 固定 |
| 迭代序 | 禁 `set` 迭代序；一切列表显式 `sorted()` |
| 时钟 | 禁 `time.time()` / `datetime.now()` 进入产物；无时间戳 |
| 落盘 | `serialize.py` 单点；manifest 双跑逐字节一致，配 `gen --check` 守门测试 |
| 图像 | PNG 无时间戳元数据（Pillow 默认不写 `tIME` chunk，M1 实测确认）；`sha256` 记入 manifest 供指纹核验 |

**`gen --check` 守门**：重新生成到临时目录 → 与既有 manifest 逐字节比对 → 差异即红。**图片本体**按 `sha256` 比对（manifest 内已登记）——**不把图片本身入 git**，故"位级一致"以 manifest 的 sha256 为锚，可核验且不污染仓库体积。

**M1 校准（D-16）**：`--check` 分**两层**判据——
1. **完整性（严格，篡改必红）**：磁盘每张图的文件 `sha256` 必须与 manifest 登记一致；任何字节改动（含 IEND 后追加）→ 红；
2. **可复现性（信息性）**：本环境重生成的 manifest 与既有 manifest 的**像素指纹**（`pixel_sha256`）必须一致（内容漂移则红）；
   若仅**文件字节**不同而像素一致 → 判为"编码器字节差异"（环境差异），如实标注、**不判漂移**。

实测：Pillow 10.4.0 与 12.3.0 对同一张图**像素 0 差异**、PNG 的 IDAT 压缩流不同；
故"跨环境位级一致"**不成立**，以 `pixel_sha256` 为跨环境内容锚、`sha256` 为环境内完整性锚。

## 七、隐私与合规

- 合成数据用假值，**不含任何真实个人信息**（data/README §三）。
- 真实用户截图**永不入库**（索引库 `*.db` 不入 git；合成图不入 git）。
- 运行期零出网（模型随 wheel 自带，无下载行为；见 plan/03 §四实测勘误）——"零上传"因此成为**可扫产物断言**的性质，而不仅是声明。
