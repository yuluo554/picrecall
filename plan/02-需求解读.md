## 一、痛点 → 能力转译

| 用户痛点（原话/场景） | 转译成的能力 | 落到哪个模块 | 可演示的验收形态 |
|---|---|---|---|
| "我记得截过一张图，上面写着 XXX，但找不到是哪张" | 按图中文字检索已囤积截图 | 模块 2 + 模块 3 | 输入查询词 → 输出命中图片路径列表（含预览缩略图） |
| 截图文件夹有数千张，翻图找不动 | 递归扫描 + 持久化索引（一次建、多次查） | 模块 1 | 一条命令建索引，第二条命令秒级查询 |
| 每次新截的图都要重跑一遍全量 | 增量索引（只处理新增/变更） | 模块 1 | 二次建索引跳过未变更文件，索引内容与文件 hash 绑定 |
| 同一个页面截了好几张，文件夹里一堆重复 | pHash 相似分组 + 保留建议清单 | 模块 4 | 输出分组 CSV，默认只读、绝不自动删 |
| "识别结果到底准不准，我自己说了不算" | 真值基准（合成图 + manifest 植入真值 + 一键对账） | 模块 5 | 基准可复跑，识别率/命中率与 manifest 对账 |
| 截图含聊天记录/账单，不敢上传 | 纯本地、零上传、零遥测 | 架构横切 | 全链路无网络调用（模型下载除外，README 声明）+ 索引库不入 git |

**一句话定位**：在成熟 OCR 引擎之上做"索引 + 检索 + 增量 + 去重"这一层；OCR 识别本身是基建，不是本项目的价值面。

## 三、非功能需求（NFR）

| 编号 | 需求 | 判据 |

| NFR-5 | 数值口径一处定义 | OCR 置信度阈值 / pHash 阈值 / 排序权重均为单一常量来源；文档只引用不复述 |

| NFR-8 | 隐私红线可核 | README 显式隐私声明；索引库路径默认落在用户指定处、不写系统共享位置 |

## 四、边界与非目标（防 scope 失控，硬清单）

**做（首期）**：本地文件夹 → OCR 索引 → 按文字检索 → 增量维护 → 相似图分组建议 → 真值基准。

**明确不做**：
1. **不做 AI 图片理解 / 语义搜索**——只做 OCR 文字检索；语义检索留扩展项。
2. **不做云同步、不上传任何内容**——隐私红线；无账号体系、无服务端。
3. **不做自动删除重复图**——误删风险不可接受；只输出保留建议清单。
4. **不做自研 OCR**——RapidOCR/Umi-OCR 已是成熟基建，本项目价值在索引层。
5. **不做剪贴板历史监听**——那是剪贴板类工具的领域，本项目只处理"已囤积的文件夹"。
6. **不做移动端 / GUI 首期交付**——首期纯 CLI；HTML 界面为扩展项。
7. **不引官方文号/政策数据**——真值全部程序化自制（data/README §二）。
8. **不承诺多语言 OCR**——首期中文+英文识别（RapidOCR 默认模型覆盖面），多语言留扩展。

**品牌隔离**：本仓库文档不提及任何姊妹项目；提及系列时只用方向级描述（"工程技术/文书处理方向"），不落具体领域名词（见 plan/06 决策记录 D-9 与 skill 阶段 0 的预防条）。

## 五、受众与时代性

- **受众**：截图囤积族、知识工作者（聊天/报错/账单截图回找）。
- **时代性**：截图数量随时间只增不减；本地 OCR/LLM 基建成熟使纯本地方案可行（RapidOCR 8146★、Umi-OCR 47925★，data/README §一）。
- **开源空白**：识别工具多、"可检索的库"没有（软论据 ⬜，检索式 `local screenshot text search ocr` 见 data/README §一）。

## 六、需求解读的实测勘误（阶段 0 预检，防"计划期猜测"带入 M1）

题目文档（v1）中对依赖的两处描述在阶段 0 预检时被实测**勘误**，详见 plan/03 §四 与 plan/06 决策记录 D-6/D-7：

| 题目文档原文（v1） | 阶段 0 实测结论 | 处置 |
|---|---|---|
| "模型首次运行下载，约 100-200MB" | `rapidocr-onnxruntime==1.4.4` 的 wheel **自带**三个 onnx 模型（det 4.53MB + rec 10.35MB + cls 0.56MB，wheel 共 14.2MB），**无需首次运行下载** | README 与 plan/03 按实测改写；台账记实测证据（wheel 内文件清单） |
| "中文分词用 wangfenjin/simple tokenizer，不可用时按字 ngram 兜底" | `libsimple` 无 cp38/Windows 的 pip 轮子（PyPI `simple-tokenizer` 仅 cp314 manylinux）；但 GitHub Release v0.7.1 提供 `libsimple-windows-x64.zip` 等预编译件，且本机 sqlite 具备 `enable_load_extension` | 主路径保留（用户提供 DLL，探测式加载）；兜底路径**由 trigram 改为逐字切分 + unicode61**——实测 trigram 对 2 字中文查询（如"账单"）返回 0 命中，不可用作兜底（见 plan/03 §三） |

> 纪律：以上结论均以"命令 + 输出"为证据，不写未实测的判断；其余未实测项（如 libsimple 实际加载成功性）在 plan/03 §四 显式标注 ⬜ 待 M1 实测。
